# Pivot — 从已知标识符扩展关系网

> 何时读：**竞品/实体型调研**，需要从已知标识符（公司名/域名/用户名/产品名）扩展出关系网时。吸收自 `7onez/cti-expert` 的 Enrich 阶段（递归 pivot）。
> 一般的事实性问答**不要**开 pivot —— 它会显著抬高请求量与跑偏风险。

## 核心动作

把每一个发现的标识符当成**新种子**，逐跳扩展：

```
种子（公司名/域名/用户名）
  ├─ 域名 → 备案信息 / WHOIS / 证书透明度 / 子域
  ├─ 公司名 → 工商注册 / 股权结构 / 分支机构 / 招聘信号
  ├─ 产品名 → 应用商店 / 舆情 / 专利 / 招投标
  ├─ 用户名 → 跨平台同名检索 / 公开投稿
  └─ 邮箱/电话 → 公开泄露库 / 公开披露文件
每一跳产出的新标识符 → 回灌为下一跳种子
```

## 停止条件（必须预设，否则无限膨胀）

满足任一即停：

1. 连续 2 跳未产出新标识符
2. 累计标识符数达预设上限（默认 50）
3. 触及红线（见下）
4. 请求预算耗尽

## 红线

- **不碰**：登录态越权、验证码破解、DRM、非公开数据库、个人隐私聚合（人肉）
- **不存**：uid、身份证、手机号等个人标识（聚合统计除外）
- 公开信息≠可任意聚合：涉及具体自然人的，只保留公开职务与公开发言，不做画像
- 签名逆向类（cKey/a_bogus/wbi）需老板明示批准，例外不构成先例

## 产出

落 `pivot-map.md`：种子 → 各跳发现的标识符 → 关系类型 → 来源（条级）。未闭合的分支写进 Open Questions，不要靠推测补。

## 与其他文件的配合

- 每个标识符的可信度按 `claims-ledger.md` 记台账
- 通道选择按 `source-dispatch.md`
- 一手材料读取纪律按 `research-discipline.md` D1
