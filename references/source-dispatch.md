# Source Dispatch — 子问题到通道的分派矩阵

> 何时读：需要决定"这个子问题该走哪条通道"时。吸收自 `Socialpranker/deepdive` §4.0。

## 为什么要分派

默认"所有子问题都丢给同一个搜索引擎"是低效的主因。定量问题走搜索会拿到一堆二手转述，定性问题走 API 会一无所获。

## 分派矩阵

| 子问题类型 | 首选通道 | 兜底 | 备注 |
|---|---|---|---|
| **定量**（规模/份额/价格/营收） | 官方 registry / 一手 API / 年报披露 | 统计局、交易所公告 | 搜索拿到的多是二手转述，优先级最低 |
| **定性**（评价/口碑/争议） | 垂直源（X/Reddit/HN/视频字幕）+ 搜索 | 社区聚合 | 注意水军与营销稿 |
| **时效**（最近发生了什么） | `anysearch`（实时） | 垂直源按时间过滤 | 注意搜索索引延迟 |
| **结构性**（谁拥有谁、关系网） | 工商/股权/备案等结构化源 | pivot（见 `pivot.md`） | |
| **技术性**（怎么实现的） | 官方文档 / 源码仓库 | 技术社区 | 文档优先于博客 |
| **中文政策类** | 政府域一手原文（gov.cn / nhsa / 省市政府 / 新华社） | — | **禁公众号/搜狐/头条转载充当原文** |
| **反爬/登录态页面** | `browser-cdp` | — | 静态 fetch 失败即转此通道 |
| **单页全文提取** | `anysearch extract`（轻量） | `baoyu-url-to-markdown`（站点适配） | extract 不支持 PDF/图片 |

## 派单三件套（子代理调研强制）

给子代理派单时必须给全，缺一则视为**无锚派单**（历史教训：v3 广州深挖无锚派单致子代理编造四级分类与 951 万数字）：

1. **已核实锚材料** — 你自己验证过的一手片段，不是"听说"
2. **来源域白名单** — 如 `gov.cn`、`nhsa.gov.cn`、省市政府域、新华社
3. **来源形态要求** — 政策原文或官方页，禁转载

回传须**条级出处**（每条断言带 source_id），无出处的数字视为未核验，不得入正文。

## 通道预算

- `anysearch`：批量搜索 1-5 并行，别一次铺 20 条查询
- `bili-daily`：日请求 160 预警 / 200 硬停 / 412 当日停（跨进程统一记账）
- `browser-cdp`：最贵，只在静态通道失败后用

## 兜底链（检索通道全挂时）

`anysearch` → 内置 `web_search` → `browser-cdp` 直连 → 本地已落盘一手材料 → 标「未核验」并停止，不给建议。
