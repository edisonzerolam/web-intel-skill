# 数字开源调查取证规范（Berkeley Protocol）

> **何时读**：需要**保全、验证、或引用**数字材料作为证据时——网页快照存证、截图取证、视频地理定位、社媒内容真伪判定。
> 纯信息检索/摘要任务不读本文件。
> **来源**：UN OHCHR & UC Berkeley Human Rights Center, *Berkeley Protocol on Digital Open Source Investigations* (2022, Advance Version), ISBN 9789210053433。章节号保留原文。

## 为什么 web-intel 需要它

普通抓取的目标是"拿到内容"；一旦这份内容要**被当作证据引用**（写进报告结论、支撑数字、作为附件），标准立刻不同：必须能证明它**没被篡改**、**来源可追溯**。Berkeley Protocol 是这一领域唯一的国际标准文本。

## 调查六阶段（Protocol Ch.VI）

| 阶段 | 关键动作 |
|---|---|
| A 在线检索 | 计划先行，避免暴露身份 |
| B 初步评估 | 判断材料是否有继续投入的价值 |
| C 收集 | 连同上下文一起采，不留孤证 |
| D **保全** | 保证材料此后不可被篡改，链式保管 |
| E **验证** | 确认材料真实、与主张相关 |
| F 调查分析 | 综合多源得出结论 |

## 保全（Preservation, Ch.VI.D）

- **chain of custody（证据链）**：每次接触、转移都留记录，能证明材料从采集到引用未经改动。
- 抓取产物应保存：**原始文件 + 采集时间戳 + 采集方式 + 来源 URL**。
- 抓取与日常浏览**分开环境**（Protocol §101–102）：避免污染证据链。

## 验证（Verification, Ch.VI.E）

对一条数字材料，逐项确认：

| 验证项 | 问什么 | web-intel 手段 |
|---|---|---|
| **来源真实性** | 账号/网站是否真是它声称的那个 | 交叉核对官方渠道 |
| **内容一致性** | 材料内部有无矛盾（光影/时间/语言/元数据） | 元数据检查 |
| **地理定位 geolocation** | 画面地点是否与主张相符 | 地标/街景比对 |
| **时间定位 chronolocation** | 画面时间是否与主张相符 | 阴影/天气/事件比对 |
| **元数据 metadata** | EXIF/上传时间/编辑痕迹 | `anysearch` 不支持二进制，用 Python 解析 |
| **首次出现时间** | 是否旧闻重发 | 反向检索 |
| **佐证 corroboration** | 是否有独立来源印证 | claims-ledger 三角验证 |

> 关键原则：**单一来源不足以确认**。Protocol 与 web-intel 的三角验证规则一致。

## 伦理与安全（Protocol Ch.II.C, Ch.IV）

数字调查会**伤到人**，这不是软约束：

- **最小化（minimization）**：只采集与调查目标直接相关的数据，不顺手囤。
- **隐私权与数据保护**（Ch.III.E）：涉及自然人的信息从严。
- **不暴露**：不得用个人账号调查；不得暴露信息来源者。
- **自护**：调查者自身也可能是目标（Protocol Ch.V.D）。

### web-intel 的落地映射

| Protocol 要求 | web-intel 现有对应 |
|---|---|
| 最小化采集 | bili-daily 只落聚合、原始零落盘 |
| 数据生命周期 | 字幕全文 24-48h 删除；元数据 ≤30 天 |
| 不存个人标识 | bili-daily 不存 uid |
| 不暴露来源 | 子代理派单脱敏、日志只记意图短语 |

## 什么时候必须升格到本规范

满足**任一**即适用：

1. 材料要作为报告结论的直接依据
2. 材料涉及具体自然人的行为/身份
3. 材料可能被用于对外发布或提交
4. 材料的真伪本身是调查目标

不满足以上任一条的普通信息检索，走常规流程即可——**不要给每次搜索都套取证规范**，那是过度工程。
